# SOS S1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 부문 멤버가 [수집 시작]을 누르면 나라장터 발주계획·사전규격·입찰공고를 모아 부문 키워드로 거르고, 사업 단위 리드 카드(점수·요약·근거)로 보여주며, 리드를 SalesTology 사업으로 전환하고 사전규격 마감 임박을 티커에 띄운다.

**Architecture:** 수집 원본은 공용 테이블(`sos_raw_items`)에 한 번만 저장하고, 부문별 분석(키워드 일치 → 사업 흐름 묶기 → 점수 → 요약)이 `sos_leads`·`sos_signals` 를 만든다. 분석 규칙은 전부 `src/features/sos/analysis/` 의 순수 함수(Vitest)이고, DB·외부 API를 만지는 코드는 `src/features/sos/server/`(server-only)에만 둔다. 실행은 화면이 서버 액션 `advanceRun` 을 반복 호출하는 단계 방식(각 호출 60초 이내).

**Tech Stack:** Next.js 16.4.2 (App Router, `cacheComponents: true`), React 19.3, TypeScript, Tailwind v4, Supabase(Postgres + RLS, `@supabase/ssr`), Vitest 5. 새 npm 의존성 없음 — 외부 API는 `fetch`.

**Spec:** `docs/superpowers/specs/2026-10-20-sos-design.md` (기능), `docs/superpowers/specs/2026-10-21-sos-visual-design.md` (화면). A 연동: `docs/integration/a-for-b.md`.

- 알림 문구 앞에 `[SOS]` 를 붙이지 않는다(`source: "SOS"`).
- 화면은 SOS 전용 다크 테마(`--sos-*` 토큰, 시각 설계서 §2~5). 리멤버 로고·이름·문구 금지. 오렌지는 버튼 채움에 쓰지 않는다.
- DB는 운영 겸용 1개. 손으로 넣는 테스트 데이터는 `[TEST]` 접두사, 끝나면 지운다.

## Review Focus

1. **정정공고·재수집** — 같은 `bidNtceNo` 가 더 큰 `bidNtceOrd` 로 다시 오거나 같은 기간을 다시 받아도 리드·원본이 중복되지 않고 갱신된다. → Task 4·7 테스트.
2. **예산 "0"/빈 값** — 발주계획 `sumOrderAmt="0"` 같은 값은 0원이 아니라 "미공개"(null)이고 점수 예산 항목은 0. → Task 3·8 테스트.
3. **KST 날짜와 D-n 경계** — `"2026-10-25 23:59:00"` 마감은 10-25 당일 D-0, 10-22 기준 D-3(알림 포함), 10-21 기준 D-4(제외). → Task 3·14 테스트.
4. **부문 위조** — 요청 본문/쿼리의 `team` 값으로 다른 부문 실행·리드를 건드릴 수 없고, 관리자는 존재하는 부문만 고를 수 있으며 [사업으로 전환]은 거부된다. → Task 3·13 테스트.
5. **동시 실행·중단** — 두 사람이 동시에 [수집 시작]을 누르면 한 실행만 생기고, 탭을 닫아 15분 넘게 heartbeat 가 없으면 실패 처리 후 다시 시작할 수 있다. → Task 10 테스트.
